# 피드의 게시글과 Story / Moment — 보존된 확장 설계

> 2026-11-13 인수인계 정리: 이 문서는 오디오 우선 출시 전의 게시글·쇼츠 구현과 데이터 계약을 보존한다. 현재 기본 앱·웹·API는 오디오만 제출·공개하며 쇼츠/게시글은 후속 범위다. 확장 형식은 `DEV_MODE=1`과 `ENABLE_EXTENDED_FORMATS=1`을 함께 지정한 명시적 로컬 회귀 환경에서만 사용한다. 기존 데이터 보존을 위해 0007을 포함한 전체 마이그레이션은 순서대로 적용한다. 현재 범위는 [동업자 인수인계](../android/docs/partner-handoff-and-backend-roadmap.md)를 따른다.

## 화면과 분류

피드의 형식 필터는 **전체 · 오디오 · 쇼츠 · 게시글**이다. 쇼츠 안에는 **All · Story · Moment**를 둔다. 전체와 All에서는 두 성격을 함께 보고, 카드 및 연속 재생 화면에 작은 성격 표시를 붙인다.

- Story: AI 드라마·상황극·연출한 이야기.
- Moment: 일상·여행·사람·장소의 추억을 편집한 영상.
- Post(게시글): 글과 선택적 사진 한 장. 승인된 공개 오디오 한 건과 공개 장소를 선택적으로 연결한다.

기존 쇼츠는 자동으로 Story나 Moment로 판단하지 않는다. 분류가 없는 콘텐츠는 All에 계속 나오며 작은 표시는 쇼츠로 유지한다. 새 앱·웹 업로드와 정보 수정에서는 업로더가 성격을 선택한다. 구버전 API 클라이언트는 분류 생략을 허용한다.

AI 생성 표시는 성격과 별개다. 실제로 기록·편집한 추억을 자동으로 AI 생성으로 표시하지 않는다. 현재 피드는 조회수에 따른 추천 가중치 없이 최신 승인 순서이며, 개인화 및 Story/Moment 노출 비율을 조절하는 추천 모델은 구현하지 않았다.

## 작성과 개인 앨범

하단 **+ 창작 → New Post**에서 초안을 만든다. 기존 미디어·ZIP 가져오기는 유지한다. 사진은 JPG·PNG·WebP, 입력 10MiB·4천만 화소 이하이며 앱에서 방향을 보정하고 긴 변 1,600px 이하 JPEG로 다시 인코딩한다. 선택한 사진 한 장만 처리하며 원본 파일·GPS·EXIF·URI는 공개하지 않는다. 초안 합계 20개/360MiB 제한을 공유한다.

개인 앨범의 Moment 상세에서 **Share → Post**는 제목·글·사진을 별도 공개 초안으로 복사한다. **Share → Moment Video**는 이미 편집한 MP4를 선택하고 원본 검사 후 제목·글과 Moment 분류를 채운 영상 초안으로 연결한다. 사진을 자동으로 영상으로 생성하지 않는다. 기존 개인 앨범은 그대로 비공개로 유지한다. 장소 이름은 초안에 복사하지만 좌표를 추정하거나 자동 공개하지 않는다. 공개 장소를 연결하려면 좌표·반경과 공개 동의를 직접 확인한다.

권리 확인·AI 표시·선택적 장소를 검토한 뒤 제출한다. 공개 업로드는 기존과 같이 승인된 크리에이터 권한이 필요하며 모든 게시글도 pending 상태에서 운영자 승인을 기다린다. 서버가 사진의 크기·해시·컨테이너 헤더를 검사한다. 실제 이미지 내용과 권리는 운영자가 확인한다.

게시글은 플레이어가 아닌 Post 읽기 화면으로 열린다. Save, 구독, 신고·차단과 로컬 History를 지원하며 Listen은 연결한 오디오를 명시적으로 재생한다. 사진은 공개 승인 ID의 API 경로에서만 최대 10MiB로 읽고, 픽셀 수를 검사해 축소 디코딩하며 제한된 메모리 캐시만 사용한다.

## 서버·클라이언트 계약

- `kind`: `audio | short_video | post`. 게시글 재생 길이는 0이고 오디오·영상은 기존 제한을 유지한다.
- `short_style`: `story | moment | null`. short_video에만 지정할 수 있다.
- `GET /v1/contents`는 `kind`, `short_style`, 검색 `q`, 구독 및 차단을 서버에서 함께 적용하고 같은 필터 내 커서 페이지를 제공한다. 성격 필터에는 `kind=short_video`가 필요하다.
- 목록은 `short_style`, `post_excerpt`(최대 180자), `has_image`를 포함한다.
- 상세의 `stream_url`은 게시글에서 null이다. 게시글 상세는 공개 글 `body`, 선택적 `place_name`, `audio_content_id`를 돌려주며 비공개 권리 진술은 제외한다.
- 사진은 기존 업로드 API에 `kind=post`, `duration_seconds=0`, 이미지 MIME 및 기존 제출 명세를 사용한다. 새 앱은 정규화한 JPEG를 제출하고 서버는 JPEG·PNG·WebP를 허용한다.
- 사진 없는 글은 `POST /v1/me/posts`에 `content_type=null`, `submission.file=null` 및 초안 UUID인 `client_id`를 보낸다. 같은 계정·초안의 재시도는 한 콘텐츠만 생성하며 payload 충돌을 거부한다.
- `submission.audio_content_id`는 공개 승인 오디오 ID만 허용한다. 상세를 읽을 때 승인 회수·차단을 다시 검사하고 접근할 수 없으면 연결을 숨긴다.
- 운영자 웹/CLI에서 게시글을 읽고 사진을 확인한 뒤 기존 revision·심사 이력 규칙으로 승인·반려·공개 중단한다.

## 마이그레이션과 검증

배포 전 `0007_posts_and_short_styles.sql`을 D1에 적용해야 한다. 로컬은 `npm.cmd run db:migrate`를 사용하며 기존 데이터를 초기화할 필요가 없다. SQL은 외래키 검사를 트랜잭션 안에서 지연하고 테이블·인덱스·생성 좌표·심사 트리거를 재구성한다. 기존 콘텐츠, 업로드, 신고와 심사 이력을 보존하며 기존 쇼츠의 분류는 null로 유지한다.

검증:

- Rust 콘텐츠 계약: 게시글의 스트림/글/길이 검증, 쇼츠 성격 제한 및 알 수 없는 값 거부.
- 서버: 글·사진 게시글의 권한/권리/해시/비공개 검수/승인, 중복 제출 방지, 검색·분류·커서, 오디오 연결 해제, 기존 데이터 마이그레이션 보존.
- Android: 형식/성격 필터, 비AI 게시글 초안의 복원·권리 검증, 사진 회전·GPS 제거·원본 보존, 기존 앨범/계정/업로드 테스트.
- 웹: 게시글 작성·검수와 Moment 쇼츠 업로드를 기존 Playwright 시나리오와 함께 검증한다.
