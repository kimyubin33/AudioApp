# 서버 계획

> 최초 결정: 2026-11-07. 운영 설명 갱신: 2026-11-13. 회사 소유 유료 Cloudflare 구성을 기본안으로 유지한다. 실제 계약·운영 연결은 완료 확인 전이며, 최신 백엔드 작업과 과금·Enterprise 계약 구분은 [동업자 인수인계](../android/docs/partner-handoff-and-backend-roadmap.md)를 기준으로 한다. 최초 출시는 오디오 우선이며 쇼츠·게시글은 후속 범위다.

## 정해진 것 (2026-11-07)

- 서버는 **구독형 클라우드**. NAS는 개발용으로만 쓴다.
- 로그인은 **Google**. 로그인 없이도 목록·재생은 가능, 신고·차단·업로드는 로그인 필요.
- 크리에이터 업로드는 **앱 안에서도, 웹에서도** 가능해야 한다. (같은 API를 쓴다)
- 크리에이터는 **승인된 사람만** 올릴 수 있고, 올린 콘텐츠도 **검수 뒤에** 공개된다.

## 선택한 구성: Cloudflare (Workers + D1 + R2)

| 역할 | 서비스 | 이유 |
|---|---|---|
| API | Cloudflare Workers | `docs/api-v1.md`의 REST 모양을 그대로 구현. 권한 검사를 전부 우리 코드로 통제 |
| 데이터베이스 | D1 (SQLite) | 콘텐츠·신고·차단·크리에이터 승인. 작게 시작하기에 충분 |
| 비공개 오디오 원본 | R2 | 저장·작업 횟수 기반 과금. 인터넷 전송량의 egress 요금은 없으나 DB·API·미디어 검사 비용은 별도 |
| 웹 업로드 페이지 | Workers 정적 자산 | 같은 도메인에서 같은 API 사용 |

**대안과 비교**
- Supabase/Firebase: 관리형 대안이다. 자체 API 계층으로 현재 계약을 맞출 수 있으나 인증·DB·스토리지 이전 작업과 실제 요금 조건을 비교해야 한다.
- 직접 만든 서버(VPS): 가장 자유롭지만 운영·보안·장애를 전부 직접 책임져야 한다.

**이전 경계:** API 계약을 유지하면 Android 변경을 줄일 수 있다. D1 스키마·트리거, R2, 인증·정리·검사 작업은 공급자 이전 시 별도 구현·검증이 필요하다.

## 사람이 해야 하는 일

1. **회사 소유 Cloudflare 계정·결제·접근 권한 설정** (<https://dash.cloudflare.com>). Workers Paid·D1·비공개 R2를 환경별로 분리하고 예산·과금·지원 조건을 확인한다. 웹사이트 Pro/Business 요금제와 Workers 과금은 별개다.
2. **Google 클라이언트 ID 만들기** → `docs/google-signin-setup.md`
3. 서비스 이름·공개 HTTPS 도메인·지원 연락처와 실제 정책 문서를 확정한다. 개발용 주소와 운영 주소를 구분하고 관리자 인증이 직접 Worker 주소로 우회되지 않게 한다.
4. 미디어 검사 작업, 전체 요청 제한, 관리자 MFA, 경보·백업·복원을 구현·검증한다. 상세 순서는 인수인계 문서를 따른다.

## 업로드 흐름 (앱·웹 공통)

크리에이터(승인된 계정)만 가능. 서버가 매번 역할과 값을 검증한다.

1. `POST /v1/uploads` — 제목·종류·길이·AI 생성 표시·파일 형식을 보낸다 → 서버가 값을 검증하고 `upload_id`와 **한 번만 쓸 수 있는 업로드 주소**(만료됨)를 돌려준다.
2. 앱/웹이 그 주소로 파일을 `PUT` 한다. (크기 상한, 허용 형식 제한)
3. `POST /v1/uploads/{upload_id}/complete` — 서버가 파일 크기·형식을 확인하고 콘텐츠를 **`pending`(검수 대기)** 로 둔다.
   기본 서비스는 MP3/M4A 오디오만 허용하며 파일 상한은 90MiB다. 영상 트랙은 거부한다. 기존 MP4/게시글 계약은 보존하지만 확장 형식은 `DEV_MODE=1`과 `ENABLE_EXTENDED_FORMATS=1`인 로컬 회귀에서만 허용한다. R2는 비공개로 두고 Worker가 공개 상태를 다시 검사한다.
4. 운영자가 검수해서 `approved`로 바꾸면 목록에 나타난다. (`rejected`면 크리에이터에게 사유 표시)
5. `GET /v1/me/contents` — 내가 올린 것과 상태를 본다.

크리에이터 승인과 콘텐츠 검수는 **운영자 전용 웹/CLI**(일반 앱과 분리)에서 한다. HTTP 승인은 오디오 형식을 제한하지만 기존 Cloudflare 직접 CLI 승인 SQL에는 같은 제한이 없어 운영 주의와 후속 일치 작업이 필요하다. CLI 상태 변경이 기본 공개 API의 확장 형식 차단을 해제하지는 않는다.
현재 크기·SHA-256·헤더 검사는 구현되어 있으나 격리된 전체 디코딩 검사와 운영자 MFA는 후속 작업이다. 기본 업로드 제한은 최근 24시간 50건/512MiB, 보관+예약 2GiB, 미완료 10개이며 운영 비용에 맞춘 확정이 필요하다.
