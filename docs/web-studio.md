# 웹 크리에이터 스튜디오와 운영자 검수

## 실행

`server/`에서 실행합니다. 기존 DB를 유지하려면 reset 대신 migrate를 사용합니다.

```powershell
npm.cmd install
npm.cmd run db:migrate
npm.cmd run dev
```

Wrangler가 웹 자산을 자동 빌드합니다. 같은 서버에서 API·웹·비공개 R2 재생을 제공합니다.

- 크리에이터: http://localhost:8787/creator
- 운영자: http://localhost:8787/admin

`0006_moderation.sql`까지 적용해야 합니다. `server/public/`은 생성 결과이므로 직접 수정하거나 Git에 추가하지 않습니다. 실제 서비스는 기존 D1/R2 생성·비밀값 설정을 마친 뒤 HTTPS 원점에 배포합니다.

## 로그인과 최초 권한 지정

앱과 같은 Google 계정을 사용합니다. 웹 OAuth 클라이언트의 **승인된 JavaScript 원점**에 실제 HTTPS 원점과 개발용 `http://localhost:8787`을 등록해야 합니다. 토큰의 audience는 서버 `GOOGLE_CLIENT_ID`와 일치해야 합니다. 클라이언트 secret을 웹이나 앱에 넣지 않습니다.

DEV_MODE=1인 loopback 서버에서는 **로컬 개발 로그인**을 사용할 수 있습니다. 새 로그인 사용자는 일반 계정이며 자동으로 크리에이터나 관리자가 되지 않습니다. 화면의 내 계정 ID를 확인한 뒤, Cloudflare 권한을 가진 운영 PC에서 기존 CLI로 최초 권한을 지정합니다.

```powershell
npm.cmd run admin -- promote <사용자id> <크리에이터id>
npm.cmd run admin -- make-admin <운영자사용자id>
```

로컬 개발 로그인은 계정 하나를 공유합니다. 이 계정으로 업로드와 검수를 모두 시험하려면 먼저 promote, 그다음 make-admin을 실행합니다. 실제 서비스에서는 업로더와 검수자의 계정을 구분해 운영할 수 있습니다. 웹에는 관리자 지정 API가 없습니다.

권한 지정 후 새로고침하면 같은 세션에서도 즉시 반영됩니다. 실제 서비스에는 기존 CLI처럼 `--remote --yes`가 필요합니다.

## 크리에이터 작업

1. 여러 MP3·M4A·MP4 또는 여러 ZIP을 선택합니다. ZIP 안의 미디어를 파일별 초안으로 펼칩니다.
2. 원본 이름·ZIP 내부 경로·크기·재생 길이·영상 해상도·SHA-256을 확인하고 직접 미리 재생합니다.
3. 제목·설명·태그·AI 표시·도구를 입력합니다.
4. 권리자·이용 근거·허락 범위·출처와 배포/인물 동의/AI 약관을 검토합니다. 체크는 권리의 자동 인증이 아닌 검수용 진술입니다.
5. 필요한 작품만 공개 장소·좌표·반경·캐릭터·스토리를 연결합니다. 웹은 현재 위치를 수집하지 않습니다.
6. 최종 명세를 확인하고 검수를 요청합니다. 승인 전에는 일반 검색·목록·재생에 공개되지 않습니다.
7. 제출 목록에서 상태·반려 사유를 확인하고 pending/rejected 작품의 정보를 수정·재검수 요청합니다. 원본·종류·길이는 유지하며 공개 중 파일 교체는 새 업로드가 필요합니다.

미디어당 90MiB, ZIP당 180MiB, ZIP 항목 최대 200개, 초안 최대 20개/총 360MiB입니다. ZIP 중앙/로컬 디렉터리·파일 범위·경로·중복·실제 해제 크기·압축률·CRC를 검사합니다. 한 ZIP의 검사 또는 저장 실패는 그 ZIP 전체를 취소하며 이미 가져온 다른 파일을 보존합니다.

ZIP은 stored/deflate 방식과 UTF-8(ASCII 포함) 이름을 지원합니다. RAR·7z·암호화·분할·ZIP64·심볼릭 링크·중첩 압축 자동 해제는 지원하지 않습니다. 비미디어 항목은 제외한 수를 알립니다. 메타데이터 디렉터리도 2MiB로 제한합니다. 지원하지 않는 레거시 문자 인코딩 ZIP은 UTF-8 ZIP으로 다시 압축해야 합니다.

해제·청크 SHA-256 계산은 전용 Worker에서 실행하며 파일별 검사 작업은 60초에 제한합니다. 브라우저 미디어 디코더가 실제로 읽을 수 있는지 확인합니다. 모든 코덱의 재인코딩이나 전체 프레임 검증은 제공하지 않으며, 운영자가 실제 소리·영상과 길이를 확인해야 합니다.

## 초안과 전송 복구

초안에는 원본 File과 권리 진술이 포함되며 IndexedDB에 저장합니다. 브라우저 저장 공간이 부족하거나 비공개 모드에서 저장을 허용하지 않으면 오류를 알립니다. 공유 PC에서는 사용 후 **기기 초안 삭제**로 제거하세요. 브라우저 저장소 삭제 시 복구할 수 없습니다.

각 저장은 읽은 저장 버전과 일치해야 합니다. 다른 탭이 먼저 바꾸면 덮어쓰지 않고 충돌을 알립니다. ZIP 하나의 초안 저장은 단일 트랜잭션입니다. 전송은 Web Locks로 파일별 중복 실행을 막습니다.

전송 전에 원본 해시를 다시 확인합니다. 세션 토큰과 업로드 URL의 비밀 token은 IndexedDB/localStorage에 저장하지 않습니다. upload_id만 보관해 새로고침/중지/응답 유실 뒤 서버 상태를 먼저 확인합니다.

- completed: 기존 콘텐츠 ID로 완료 처리합니다.
- uploaded: 파일을 다시 올리지 않고 complete를 재시도합니다.
- created/uploading/failed/expired: 이전 전송을 폐기한 뒤 새 전송을 만듭니다.
- 확인할 업로드가 남아 있는 동안에는 정보 수정을 잠급니다. **현재 전송 폐기 후 수정**으로 풀 수 있습니다.

세션 만료 뒤에는 다시 로그인해야 하며 원본과 초안은 유지됩니다. 전체 요청 단위의 재시도이며 파일 중간 바이트부터 이어 올리는 multipart/resumable 업로드는 아닙니다.

## 운영자 검수

관리자만 검수 목록·비공개 권리 진술·이력에 접근합니다. 서버가 각 요청과 변경 시 DB의 역할을 확인합니다.

- 검수 대기/공개 중/반려/공개 중단 목록을 구분해 조회합니다.
- 비공개 R2 원본을 직접 재생하거나 내려받아 파일·길이·코덱을 확인합니다.
- 권리 진술과 공개 메타데이터를 검토하고 세 가지 확인을 마쳐야 승인 버튼이 활성화됩니다.
- 열어 본 revision과 현재 revision이 같아야 승인·반려·공개 중단을 적용합니다. 크리에이터가 중간에 수정하면 409로 막고 다시 검토해야 합니다.
- 반려·공개 중단 사유는 1~200자입니다. 원본이 R2에 없는 외부 샘플의 웹 승인은 지원하지 않으며 기존 CLI에서 확인합니다.
- 신고는 사유별 건수를 보여줍니다. 심사 이력에는 버전·이전/이후 상태·검토자·사유·시각을 남깁니다. 화면에는 최근 50건, DB에는 전체 이벤트를 보관합니다.
- 기존 CLI의 승인·반려·공개 중단도 같은 트리거로 이력을 남기며 검토자는 cli로 표시합니다. 마이그레이션 이전의 과거 작업을 소급 생성하지 않습니다.

운영 화면에서 사용자 ID로 조회해 크리에이터 승인/업로드 권한 회수를 할 수 있습니다. 최초 creator_id는 변경하지 않습니다. 권한 회수는 새 업로드를 막고 기존 콘텐츠의 공개 상태는 유지합니다. 콘텐츠를 내리려면 해당 작품을 별도로 공개 중단합니다.

## 브라우저 보안

프로덕션 세션은 호스트 전용 `__Host-` 쿠키이며 Secure·HttpOnly·SameSite=Strict·Path=/, 수명 1시간입니다. loopback DEV 서버에서만 별도 개발 쿠키를 허용합니다. 쓰기 요청은 같은 Origin과 X-Audio-Web 헤더를 모두 요구하며 교차 원점 CORS를 열지 않습니다. 기존 Android Bearer 인증과 함께 사용할 수 있습니다.

CSP는 자체 스크립트/Worker와 Google 공식 로그인 SDK만 허용합니다. 사용자 입력은 DOM textContent/value로 렌더링하고 HTML로 실행하지 않습니다. 비공개 응답과 웹 문서는 no-store이며 원본 URL token을 외부 referrer로 보내지 않습니다.

브라우저 전송 URL은 서버가 지정한 같은 원점의 정확한 업로드 경로만 허용합니다. 앱 전용 API_BASE_URL이 로컬 TLS 프록시를 가리키더라도 웹 쿠키를 그 원점으로 보내지 않습니다.

## 검증

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run web:test
```

서버/ZIP 테스트는 격리된 Workers·D1·R2를 사용합니다. Playwright 테스트도 별도 테스트 서버·DB·브라우저 프로필에서 AAC 파일을 직접 생성해 다음을 확인합니다.

- 여러 정상 ZIP과 경로 조작 ZIP의 분리, 초안 복원, 전체 검토와 실제 브라우저 PUT
- 실제 AAC 오디오와 H.264/AAC 쇼츠의 트랙·해상도·미리 재생, 영상 트랙 없는 MP4 거부, 미리 재생 화면을 떠날 때 수신·재생 자원 해제
- 비공개 제출 → 오래된 버전 승인 거부 → 반려·수정·재제출 → 승인·Range 재생 → 공개 중단
- HttpOnly 세션, 일반 계정/비로그인의 관리자 접근 차단, 탭 간 초안 충돌
- 데스크톱/모바일 폭 화면과 수평 넘침

Windows는 설치된 Edge를 사용합니다. 그 외 환경은 Playwright Chromium 설치가 필요합니다. 실제 Google 팝업/프로덕션 OAuth와 모든 모바일 브라우저 코덱은 별도 실기기 확인 대상입니다. 테스트는 실제 서비스 사용자나 작품을 만들거나 승격하지 않습니다.

차량 GPS 수신과 차량↔폰 자동 전환은 기업의 SDK/API·인증·데이터 제공 계약이 준비될 때 연결할 작업으로 보류합니다. 현재 웹 업로드와 검수는 차량 연동 없이 완결됩니다.
