# 추억 앨범 전환 — 이전 확장 기획

> 2026-11-13 인수인계 정리: 아래의 “현재”는 2026-11-09 추억 앨범 확장 시점의 구현 기록이다. **최초 출시는 오디오 우선**으로 변경되어 카메라·Moment·게시글·쇼츠 진입은 기본 앱에서 숨기고 공개 제출·노출도 오디오로 제한했다. 관련 데이터·코드는 후속 호환을 위해 보존한다. 최신 범위와 남은 서버 작업은 [오디오 우선·Drive](../android/docs/audio-first-drive.md), [동업자 인수인계](../android/docs/partner-handoff-and-backend-roadmap.md)를 기준으로 한다.

기준: ‘추억 앨범 제품 판단 및 기술 설계서 v0.3’(2026-11-09)와 AI & I 화면 시안.
이번 변경은 기존 Android / Rust / Cloudflare Workers·D1·R2 구현 위에 적용한다.
문서의 Next.js·PostgreSQL 구성을 새로 배포하거나 기존 서버를 대체하지 않는다.

## 현재 이용 가능한 흐름

- 피드: 승인된 오디오·쇼츠·게시글의 통합 목록, 형식별 필터와 검색. 쇼츠는 All·Story·Moment로 구분하고 연속 감상에서도 같은 필터를 사용한다.
- 상단 카메라 → Moment, 또는 보관함의 계정 메뉴 → Moments → New: 한 장의 사진, 제목·본문, 선택적인 장소 이름 → 기기 앨범 저장 → 상세 감상·삭제.
- 편집은 자동 저장되며, 사진 선택기나 다른 화면에서 돌아와도 이어 쓴다. 기기 앨범은 로그인과 무관하고 서버에 동기화하지 않는다.
- 꾸며보기: 프롬프트 3종 복사, 가져온 글과 현재 글 비교, 선택 적용, 적용 전 글로 되돌리기. 사진·파일 후보의 비교 편집은 아직 제공하지 않는다.
- 개인 Moment 상세의 Share 또는 + 창작 → New Post: 사진·글의 별도 공개 초안, 선택적 공개 오디오 연결, 권리 확인·크리에이터 권한·검수 후 게시글 공개. [게시글·쇼츠 확장](feed-formats.md).
- + 창작 → 스트리머 모드: 오디오·쇼츠를 가져오기·미리보기·권리 확인·검수 제출. 파일/ZIP, 체크섬, 반려 후 수정과 R2 비공개 저장을 유지한다.
- 지도 메뉴: 장소 이름으로 공개 콘텐츠 검색, 명시적으로 켜는 주변 탐색(기본 1km), 공개 장소를 외부 지도 앱에서 열기. 앱 안에 지도 타일을 표시하는 SDK는 아직 없다.
- 보관함: Saved / History. 상단 원형 계정 버튼에서 로그인·프로필 수정·Moments·차단 목록·기록 삭제·앱 권한·로그아웃을 연다.
- 구독·신고·차단·Media3 백그라운드 재생 유지.

사진 앨범은 ‘나만 보기’로 표시하고 기기 저장·앱 삭제 시 함께 삭제됨을 짧게 안내한다.
피드·지도·편집 화면의 소개 문구를 제거했다. 헤더는 글자 대신 벡터 브랜드 심볼을 사용한다.
현재 공개 목록은 친구 피드가 아닌 기존 승인 콘텐츠 목록이다.
친구 공유가 없는 상태에서 친구에게 게시됐다는 성공 메시지나 공개 선택지를 제공하지 않는다.

## 계정 프로필

기존 Google Credential Manager / Rust 로그인과 GET /v1/me를 사용한다.
프로필 화면을 여는 것만으로 개발 계정에 자동 로그인하지 않는다. 개발용 로그인 버튼은 debug의 DEV_LOGIN 환경에서만 표시한다.
로그인·토큰 만료·로그아웃 변경은 토큰 값 없이 관찰하며, 새 계정 확인 전에 이전 이름과 사진을 지운다.
늦게 도착한 계정 응답과 이전 계정의 편집 요청은 새 계정 화면에 적용하지 않는다.
명시적 로그아웃 후에는 debug의 자동 재로그인도 중지한다. 앱 토큰 제거와 Credential Manager 상태 초기화를 수행한다.

이름·사진은 noBackupFilesDir/profiles 아래에 계정별로 분리해 저장한다. 서버 프로필 동기화는 아직 없다.
JPEG·PNG·WebP 10MiB/40MP 이하를 실제 디코딩하고 방향을 보정해 정사각형 최대 512px JPEG로 저장한다.
GPS/EXIF와 선택기 원본 URI는 보관하지 않는다. 사진은 선택 즉시 저장하고 이름은 Save로 확정한다.
색인은 AtomicFile로 기록하며 참조가 사라진 사진은 같은 계정 디렉터리에서만 정리한다.
기존 Saved / History와 개인 Moments는 기기 내 데이터이며 로그아웃만으로 삭제하지 않는다. 기록 삭제는 별도 확인을 받는다.

로고는 직접 만든 파형·사람 심볼이다. Gemini를 연상시킬 수 있는 네 갈래 별은 제거했다.
브랜드 참고: [Google 브랜드 안내](https://about.google/brand-resource-center/guidance/). 다른 서비스의 로고를 자체 브랜드에 결합하거나 공식 관계를 암시하지 않는다.
이 변경은 법적 권리 확인이나 상표 등록 가능성을 보증하지 않는다.

## 사진·초안 저장

저장 위치는 Android noBackupFilesDir의 memory-album. Android 앱의 전용 저장소이며 클라우드/기기 백업에서 제외된다.
파일 선택기의 임시 URI는 보관하지 않는다. 사용자 좌표를 읽거나 EXIF GPS를 장소로 자동 입력하지 않는다.
선택적 장소는 사용자가 적은 이름이고, 공개 지도 좌표라고 주장하지 않는다.

입력 JPEG·PNG·WebP 10MiB 이하, 최대 40MP. 긴 변을 최대 1920px 이내로 샘플링하고 EXIF 방향을 적용한 뒤 JPEG로 인코딩한다.
GPS·원본 카메라 메타데이터는 출력에 복사하지 않는다. 현재는 사진 한 장, 앨범 200건, 사진 저장량 약 200MiB로 제한한다.
색인/초안은 AtomicFile로 기록하고, 기록 확정 후 참조가 없는 사진만 정리한다.
읽기 실패 시 기존 파일을 덮어쓰지 않는다. 실패 메시지와 재시도를 제공한다.
가져오기·저장·삭제는 직렬화하고 저장 중 중복 제출을 막는다.
저장 트랜잭션은 화면 이동으로 중간 취소되지 않도록 한다.
앱 삭제 시 함께 삭제된다. 계정별 보관·동기화·내보내기는 후속이다.

## 이어서 구현할 서버 범위

v0.3 전체의 친구 공유는 현재 공개 콘텐츠 모델과 다른 권한 경계다.
사진 게시를 기존 ‘크리에이터 승인 후 전체 공개’ API에 억지로 연결하지 않는다.

1. posts/revisions/assets를 추가하고 private/friends/public, map_enabled, car_enabled, car_audio_id를 각각 관리.
2. 무작위 친구 코드, 수락된 친구 관계, 차단·해제, 요청 빈도 제한과 코드 재발급.
3. 사진/오디오/영상 격리 업로드 → 검사·표준화 작업자 → READY 버전 확정. EXIF 제거와 변환된 파일만 제공.
4. 피드·상세·장소 목록·반응·저장·차량 목록·재생마다 같은 열람 권한 재검사. 공개 축소·차단·삭제 후 새 재생 URL 발급 금지.
5. 하트·저장과 실제 인기 신호를 기록한 후, 허용된 게시물 안에서 인기 오디오 추천을 계산. 조회수를 임의 생성하거나 최신순을 인기순으로 표시하지 않음.
6. 사진 추억의 친구/공개 게시와 파일 후보 비교를 이 권한 모델에 연결하고 교차 계정 회귀 테스트 추가.

## 차량 방향

차량에서 특정 인기 게시물의 오디오를 추천하는 방향을 유지한다.
음성만으로 이해되는 감상용 트랙, 작성자의 차량 재생 동의, 요청자의 열람 권한을 모두 충족하는 항목이 대상이다.
장소가 없어도 차량에서 들을 수 있으며, 장소 접근만으로 자동 재생/알림을 시작하지 않는다.
기존 Media3 오디오 세션과 수동 재생은 유지한다.

기업의 차량 GPS SDK/API, 차량↔휴대전화 위치 소스 전환, 실제 차량 화면·인기 추천 연동은 보류한다.
새 친구 게시물의 차량 허용·전용 큐·인기 정렬 API는 아직 구현하지 않았다.
위 조건을 갖추기 전에는 새 사진 추억을 차량 추천에 넣지 않는다.

## 검증

Android 계측 테스트에서 실제 JPEG의 EXIF 방향 적용·GPS 제거·원본 보존, 초안·후보 복원,
색인 오류/경로 탈출 거부, 10MiB 초과 거부와 기존 앨범 유지, 글 후보 적용·되돌리기·저장·재열기를 확인한다.
개인정보는 실제 사용자 파일 대신 테스트가 만든 합성 이미지로 검증한다.
화면은 Compose 미리보기(휴대전화/큰 창)와 에뮬레이터로 확인한다.
테스트는 기존 JUnit4·AndroidJUnitRunner와 Compose 동작 테스트를 사용한다. 외부 서버 대신 임시 전용 앨범을 주입한다.
Compose v2 테스트 규칙과 상태 복원 검사로 후보 편집 상태를 검증하며, 실제 앱과 같은 시스템 안전 영역을 적용한다.
Espresso는 Android 17에서 제거된 InputManager 리플렉션을 쓰지 않는 3.7.0으로 조정했다.
근거: [AndroidX Test 릴리스 노트](https://developer.android.com/jetpack/androidx/releases/test#espresso-3.7.0).
명령: Android 폴더에서 gradlew.bat :app:testDebugUnitTest :app:connectedDebugAndroidTest :app:lintDebug.
Windows PATH에 인용 부호가 있으면 README의 해당 안내대로 이번 PowerShell 세션에서만 정리한다.
