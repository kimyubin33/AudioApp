# ZIP 가져오기 검증과 취소

기준일: 2026-11-12. MED-01 중 클라이언트 파일 가져오기 검증을 정리한다.
[출시 체크리스트](google-play-release-readiness.md)와 함께 관리한다.

## 공통 제한

- 한 번에 선택하는 입력 파일 최대 20개.
- 초안 최대 20개, 저장하는 원본 합계 최대 360 MiB.
- ZIP 원본 최대 180 MiB, 중앙 파일 목록 최대 2 MiB·200개 항목.
- ZIP의 항목별 해제 크기 최대 90 MiB, 전체 해제 크기 최대 360 MiB.
- 항목별 실제 크기는 압축 크기의 100배 이하여야 한다. 미디어가 아닌 항목도 계산·검사한다.
- Stored/Deflate 압축만 지원한다. 암호화·분할·ZIP64·심볼릭 링크·특수 파일은 거부한다.
- ZIP 내부 ZIP 등 지원하지 않는 파일은 체크섬 확인 후 제외하며 재귀적으로 해제하지 않는다.
- 이름은 UTF-8로 검사한다. 다른 문자 인코딩의 오래된 ZIP은 UTF-8 이름으로 다시 압축해야 할 수 있다.

## 검증 순서

Android는 선택한 content URI에서 앱 전용 UUID 파일로 제한된 크기만큼 복사한다.
ZIP의 끝 정보·중앙 파일 목록을 먼저 확인하고 실제 압축 항목과 대조한다.
이 임시 ZIP은 성공·실패·취소 시 정리하며, 프로세스 종료 후 남으면 기존 초안 고아 파일 정리가 처리한다.

Android와 웹 모두 다음을 확인한다.

1. 경로 탈출, 절대 경로, 빈 경로 구간, 앞뒤 공백, 제어·방향 제어 문자.
2. Unicode NFC 정규화와 대소문자를 고려한 중복 경로.
3. 중앙/로컬 파일명·압축 방식·플래그·크기·CRC 및 데이터 설명자의 일치.
4. 파일 영역 중첩과 중앙 목록/파일 끝의 범위.
5. 실제 읽은 해제 바이트 수와 CRC. 제외하는 비미디어 항목도 끝까지 검사한다.
6. 원본 SHA-256, 미디어 메타데이터 및 길이, 오디오 전용 범위.
7. 하나의 ZIP 검사가 전부 성공한 뒤 초안에 반영한다.

ZIP 경로는 표시용이며 Android 출력 파일 경로는 앱이 생성한 UUID다.
웹은 원본을 Worker에서 검사하고 성공한 묶음만 IndexedDB에 저장한다.
하나의 ZIP이 실패하면 그 ZIP에서 만든 초안을 폐기한다. 다른 정상 ZIP과 기존 저장 초안을 덮어쓰지 않는다.

Android의 초안 용량은 실제 저장한 미디어만 계산한다. 제외 항목이나 실패한 ZIP의 바이트가
이후 정상 파일의 초안 용량에 잘못 남지 않도록 했다.

## 취소와 복구

웹의 **가져오기 중지**는 압축 해제·해시 Worker를 종료하고 미디어 메타데이터 읽기를 중지한다.
임시 미디어 URL과 이벤트·타이머도 정리한다. 아직 저장하지 않은 현재 묶음과 이후 입력은 반영하지 않는다.
이미 저장을 시작해 완료한 IndexedDB 묶음은 유지한다. 취소 뒤 같은 파일을 다시 가져올 수 있다.
Worker 검사에는 기존 60초, 브라우저 미디어 메타데이터에는 20초 시간 제한이 적용된다.

Android는 복사·압축 항목 검사·읽기 중과 파일 사이에서 코루틴 취소를 확인한다.
취소 시 해당 가져오기 작업이 반환하기 전 생성한 파일을 정리한다.
기존 저장 초안은 유지하며 ViewModel의 고아 파일 정리도 함께 수행한다.
플랫폼 MediaMetadataRetriever 호출 자체를 강제 중단하는 격리 프로세스는 아직 구현하지 않았다.

## 오디오 확인 범위

Android는 영상 트랙이 있거나 오디오 트랙이 없는 파일을 거부하고 MIME·길이를 확인한다.
웹은 메타데이터 읽기에서 영상 크기를 확인해 영상 파일을 M4A로 이름만 바꾼 경우를 거부한다.
기존 미리 재생 확인과 권리 확인은 계속 필요하다.

클라이언트는 신뢰 경계가 아니다. 이 검사는 서버에서 디코딩 가능 여부를 검증한 것이 아니다.
서버의 기존 크기·해시·헤더 검사를 통과하더라도 실제 전체 디코딩·코덱·실제 길이 검증은
격리 처리 환경에서 추가해야 한다. 손상된 후반부, 악성 미디어 디코더 입력, 권리 적법성은 별도 검증 범위다.

## 검증 기록

- Android CreatorZipArchiveTest: 정상 Stored/Deflate·데이터 설명자, 끝 정보/로컬 불일치,
  제외 항목 CRC, 정규화 중복, 암호화·링크·ZIP64·개수/전체 크기 제한, 취소·부분 파일 정리.
- 기존 CreatorFileRulesTest: 실제 바이트 상한, SHA-256 변경 감지, 경로와 압축률.
- 웹 web-import.test.mjs: 구조·CRC·중복·할당량·특수 파일·제외 항목·중첩 압축.
- 웹 E2E: 기존 초안 유지 → 검사 취소 → 새로고침 → 재가져오기, M4A로 위장한 영상 거부.

2026-11-12 검증 결과: 서버/웹 단위 테스트 75개, 웹 E2E 11개 통과.
Android ZIP 신규 7개를 포함한 단위 테스트, 앱 빌드·lint, TypeScript 검사가 성공했다.
DB 변경과 운영 배포는 이번 단계에 포함하지 않았다.

참고 API: [Java ZipFile](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/zip/ZipFile.html).
Android 기기별 미디어 지원과 장시간·대용량 실기기 검증은 추가로 수행한다.
