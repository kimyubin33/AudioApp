# 계정 삭제·정책 동의 운영 연결

기준일: 2026-11-12. 구현된 기능의 연결 절차이며 운영 배포나 법률 검토 완료를 의미하지 않는다.
전체 남은 작업은 [출시 준비 체크리스트](google-play-release-readiness.md)를 따른다.

## 적용 순서

1. 운영 DB 백업과 복구 절차를 확인한다. 기존 데이터에 `0008_account_lifecycle.sql`을 적용한 다음 새 Worker를 배포한다. 이전 마이그레이션도 순서대로 있어야 한다.
2. 공개 HTTPS 문서 및 문의 창구를 준비하고 아래 Worker 환경값을 등록한다.
3. 운영 `DEV_MODE`를 제거하거나 `0`으로 둔다. 운영 D1 ID, 비공개 R2, Google OAuth 설정을 검증한다.
4. 웹 정적 자산을 빌드하고 Worker와 함께 배포한다. `/delete-account`를 비로그인 브라우저에서 확인한다.
5. 앱 운영 API 주소·OAuth ID를 설정하고 서명된 테스트 빌드로 검증한다.
6. Play Console의 계정 삭제 URL·개인정보처리방침 URL을 실제 배포 주소로 등록한다.

로컬 DB에만 적용하는 명령 (작업 디렉터리 `server`):

```powershell
npx.cmd wrangler d1 migrations apply audioapp --local
```

운영 적용은 별도 배포 작업이다. 이 문서가 운영 DB 변경·삭제 완료의 증거는 아니다.
기존 개발 DB를 초기화하거나 사용자 데이터를 지워서 마이그레이션을 우회하지 않는다.

## 정책 설정

| Worker 환경값 | 의미 |
| --- | --- |
| POLICY_VERSION | 1~64자 영문·숫자·점·밑줄·하이픈으로 된 문서 묶음 버전 |
| TERMS_URL | 실제 서비스 이용약관의 공개 HTTPS 주소 |
| PRIVACY_URL | 실제 개인정보처리방침의 공개 HTTPS 주소 |
| CREATOR_TERMS_URL | 배포 이용허락·금지 콘텐츠·권리·검수 기준을 담은 크리에이터 약관 주소 |
| SUPPORT_EMAIL | 실제 운영자가 대응하는 문의 이메일 |

`GET /v1/legal`은 공개 링크·버전·준비 상태를 반환한다. 필수 설정이 빠지면 운영 가입/제출은 `policy_unavailable`로 차단한다.
링크 문서의 접근 가능 여부나 법적 적정성을 URL 문법 검사로 판단하지 않는다. 운영자가 로그인 없이 문서를 열어 확인해야 한다.

가입 교환 요청에는 `policy_version`이 필요하다. 크리에이터는 `POST /v1/me/policies/creator`에
`{version, accepted:true}`를 보내며, 업로드 권한 검사에서도 현재 버전 수락을 확인한다.
D1 `policy_acceptances`는 사용자·종류(service/creator)·버전·최초 수락 시각을 저장한다. 동일 버전 재요청은 중복 저장하지 않는다.
동의 증명을 위한 IP·기기 식별자는 추가 수집하지 않는다.

현재 구현은 서비스/크리에이터 약관 수락이다. 선택적 개인정보 처리 동의·철회 원장, 국외 이전 동의, 연령 확인 등은
실제 사업 요건을 확정한 뒤 별도로 구현한다. 개인정보처리방침 공개 자체를 포괄 동의로 표시하지 않는다.
문서를 변경할 때 이전 버전 원문도 보존하고 재동의가 필요한 변경인지 운영자가 결정한다.
기존 로그인 세션 전체에 대한 변경 알림·서비스 약관 재동의 정책은 후속 작업이다.

## 출시 빌드 설정

개발자 전역 Gradle 속성 또는 CI의 Gradle 인자로 `releaseApiBaseUrl`, `googleWebClientId`를 공급한다.
API 주소는 운영 HTTPS 원점이어야 한다. 앱 API 경로·쿼리·계정 정보·로컬 IP·예약 placeholder는 허용하지 않는다.
`:app:validateReleaseConfiguration`이 `preReleaseBuild`에 연결되어 누락된 설정으로 릴리스 빌드를 진행할 수 없다.
이 검사는 운영 서버의 가용성, OAuth 실제 소유권, Play 서명 설정을 대신하지 않는다.
개발용 주소는 debug에만 유지한다. 비밀값·서명 비밀번호를 저장소에 기록하지 않는다.

## 삭제 API 및 상태

- 앱: `POST /v1/me/deletion`, 서비스 Bearer 토큰 + 최근 Google ID 토큰 + `confirm:"DELETE"`.
- 웹: `POST /v1/web/account-deletion`, 최근 Google ID 토큰 + 동일 원점/커스텀 헤더 + 동일한 명시적 확인.
- 웹페이지: `/delete-account`. 앱 설치나 신규 서비스 가입 없이 Google 계정 확인 후 요청한다.
- 재인증: 서명·발급자·대상·만료 및 최근 5분 내 발급 시각을 검증한다. 다른 계정으로 현재 계정을 지울 수 없다.
- `202 {status:"pending"}`: 삭제 접수. 삭제 완료가 아니다. 기존 토큰 요청·새 제출·재가입을 차단하고 공개 콘텐츠를 즉시 내린다.
- 웹에서 해당 Google 계정의 서비스 사용자가 이미 없으면 `200 {status:"deleted"}`. 신규 사용자를 생성하지 않는다.
- 이미 접수된 요청은 같은 Google 증명으로 재시도할 수 있다.

서버는 계정을 삭제 대기 상태로 남기고 R2 삭제 키 목록을 D1에 저장한다.
업로드 중인 요청을 고려해 `max(접수 시각, 해당 계정 업로드 만료 시각)+1시간` 이후 정리한다.
매시 17분 cron이 최대 10계정, 계정별 100개 객체를 처리한다. 파일이 많거나 장애가 있으면 여러 회차가 필요하다.
R2 삭제 성공 후에만 키를 목록에서 제거한다. 실패하면 다음 cron에서 재시도한다.
전송 도중 탈퇴한 PUT도 완료 시 계정 상태를 재검사하고 파일을 제거한다.

모든 객체가 삭제되면 계정·업로드·콘텐츠·구독·차단·해당 신고/심사·동의 기록을 삭제한다.
다른 콘텐츠의 운영 이력에 남은 삭제 계정의 운영자 식별자는 익명화한다.
현재는 별도 법정 보존 영역을 구현하지 않았다. 보존 근거가 확정되면 최소 자료·기간·접근 통제를 설계하고 삭제 안내와 함께 갱신한다.
백업·CDN·외부 로그에 남는 데이터의 삭제/보존은 실제 운영 인프라에서 별도로 확인한다.

앱은 접수 확인 후 현재 재생을 중지하고 토큰·해당 계정의 로컬 프로필·연결된 제출 초안을 정리한다.
미제출 초안·기기 공용 청취 기록·저장 목록과 웹 브라우저 초안은 자동 삭제하지 않으며 화면에서 이 범위를 설명한다.
로컬 정리 실패 시 별도 안내한다. Google 계정 자체는 삭제하지 않는다.
다른 기기의 로컬 자료 정리와 삭제 완료 알림/문의 대응 절차는 후속 운영 작업이다.

## 운영 관찰 및 복구

- `account_deletions`의 처리 대기 수와 가장 오래된 `purge_after`를 관찰한다. 장기 대기는 경보 대상으로 설정한다.
- `account_deletion_objects`에 키가 남으면 파일 삭제가 아직 끝나지 않았다.
- R2 오류 시 삭제 대기 행이나 사용자 행을 수동으로 먼저 지우지 않는다. 원인을 해결하고 cron을 재실행한다.
- 로그 `account deletion retry required`는 재시도 필요 신호다. Google ID 토큰·파일 키·사용자 식별자는 로그에 출력하지 않는다.
- 정해진 삭제 처리 기한, 지연 통지, 담당자, 백업 보존은 회사가 확정해야 한다.
- `TOKEN_SECRET` 변경은 기존 세션을 일괄 무효화한다. 개별 로그아웃의 서버 토큰 철회·관리자 MFA는 별도 남은 작업이다.
