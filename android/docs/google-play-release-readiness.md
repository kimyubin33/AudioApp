# Google Play 출시 준비 및 후속 개발 체크리스트

> 점검 기준일: 2026-11-12
> 대상: AudioApp의 오디오 중심 최초 출시
> 상태: **출시 준비 중 — 운영 서버 연결, 계정 삭제, 정책·동의 흐름 보완 필요**

이 문서는 코드 점검 결과와 남은 작업을 이어서 개발하기 위한 기준 문서다. 체크박스는 구현뿐 아니라 아래 완료 조건과 검증을 충족한 경우에만 체크한다. 실제 Cloudflare 운영 환경, Play Console 비공개 설정, 회사 계약·법률 요건은 이번 점검에서 확인하지 못했다. 해당 항목은 미확인이지 위반이 확인된 것은 아니다.

점검은 당시 로컬 작업 트리를 기준으로 했다. 아직 커밋되지 않은 앱·서버 변경도 포함되므로 GitHub 코드와 일시적으로 차이가 있을 수 있다. 이 문서를 저장하는 커밋은 출시 승인이나 앱 전체 구현 완료를 의미하지 않는다.

## 1. 제품 범위와 다음 작업 원칙

- 최초 출시의 핵심은 **이미 만들어진 AI 오디오의 업로드·검색·재생·구독·보관**이다.
- 앱이 오디오를 직접 생성하는 제작 도구로 설명되지 않도록 한다.
- 쇼츠·게시글은 후속 업데이트 범위다. 앱·웹·서버의 공개 기능을 같은 범위로 맞춘다.
- 위치는 선택적인 콘텐츠 발견 기능이다. 위치를 거부해도 기본 검색·재생이 가능해야 한다.
- 추천 알고리즘 설계는 동업자 담당이다. 출시 준비 작업에서 임의로 추천 정책을 확장하지 않는다.
- 기업·OEM 제공이 필요한 연동은 의존성을 명시하고, 독립적으로 가능한 계정·약관·품질 작업부터 진행한다.
- 차량 먹물 화면은 현재 debug용 Ink Studio 디자인 시뮬레이션이다. 실제 내비게이션, 현대차 OEM 연동, Android Auto의 사용자 지정 그래픽 패널이 아니다.
- 출시 문구·스크린샷에는 실제 배포 버전에서 사용할 수 있는 기능만 표시한다.

## 4. 백엔드 작업과 완료 조건

### REL-01 — 운영 환경 연결

확인된 상태:

- [app/build.gradle.kts](../app/build.gradle.kts)의 release API_BASE_URL은 `https://api.example.invalid`다.
- [server/wrangler.toml](../../server/wrangler.toml)의 database_id는 영(0)으로 구성된 개발용 값이다.
- Google 로그인은 구현되어 있다. 실제 운영 OAuth 및 서명 인증서 설정은 별도 확인이 필요하다.

작업:

- [ ] 운영 Workers·D1·비공개 R2·도메인·HTTPS를 구성한다.
- [ ] 운영 마이그레이션 적용과 초기 관리자 생성 절차를 문서화한다.
- [ ] 운영 비밀값을 비밀 관리 기능에 등록한다. 키·토큰·인증서 비밀번호는 Git에 넣지 않는다.
- [ ] 운영 DEV_MODE를 비활성화하고 개발용 로그인 토큰이 거부되는지 확인한다.
- [ ] Google OAuth 웹/Android 클라이언트와 Play App Signing 인증서 설정을 검증한다.
- [ ] 잘못된 배포 URL·필수 설정 누락을 릴리스 검사에서 차단한다.
- [ ] 실제 출시 빌드로 비회원 탐색 → 로그인 → 크리에이터 제출 → 검수 → 공개 재생을 검증한다.

완료 증거: 비밀값을 제외한 배포 버전·환경 식별, 마이그레이션 결과, 운영 통합 테스트 결과를 남긴다. 개발 서버에서 성공한 결과로 대체하지 않는다.

### ACC-01 — 계정 삭제

확인된 상태: [계정 화면](../app/src/main/java/com/kimyubin33/audioapp/ui/AccountScreens.kt)에는 로그아웃과 청취 기록 삭제가 있지만 회원 탈퇴는 없다. [계정 생성](../../server/src/accounts.ts)은 Google sub로 DB 사용자를 만들고, [라우팅](../../server/src/index.ts)에는 계정 삭제 API가 없다.

- [ ] Account에 계정 삭제 진입점·영향 설명·확인·필요한 재인증을 제공한다.
- [ ] 삭제 요청 API에 본인 확인·권한 검사·중복 요청 안전성을 구현한다.
- [ ] users, 구독, 차단, 초안/업로드, 공개 콘텐츠, R2 파일, 신고·검수 이력의 삭제/보존 범위를 확정한다.
- [ ] 정당하게 보존해야 하는 자료는 근거·기간·접근 제한을 문서화한다. 단순 비활성화를 탈퇴 완료로 표시하지 않는다.
- [ ] DB와 R2 삭제가 부분 실패해도 재시도할 수 있는 상태·작업 구조를 마련한다.
- [ ] 삭제 즉시 접근을 제한하고 기존 세션의 후속 요청을 거부한다.
- [ ] 삭제 진행·완료·실패 안내와 로컬 프로필/토큰/기록 정리 범위를 구현한다.
- [ ] 앱을 재설치하지 않고 삭제를 요청할 수 있는 공개 웹페이지를 만든다.
- [ ] 해당 URL을 Play Console에 등록한다.

완료 증거: 타인 삭제 거부, 중복 요청, 전송 중 탈퇴, 공개 콘텐츠 삭제, R2 오류 후 복구, 기존 토큰 재사용 거부를 검증한다.

### UGC-01 — 신고와 운영 조치

확인된 상태: 콘텐츠 신고와 크리에이터 차단은 존재한다. 현재 관리자 API는 신고 사유별 건수 중심이며, 사용자 자체 신고와 신고 상세·처리 상태 관리가 부족하다.

- [ ] 콘텐츠 신고와 별도로 사용자/크리에이터 신고를 지원한다.
- [ ] 신고 설명·증거·접수 시각·처리 상태를 운영자가 확인할 수 있게 한다.
- [ ] 접수 → 검토 → 조치/기각 → 통지 → 이의제기 흐름과 책임자를 정한다.
- [ ] 콘텐츠 비공개 전환, 반복 위반 계정 제한, 권한 회수, 감사 기록을 연결한다.
- [ ] 저작권·음성 사칭·개인정보 노출 신고 접수 경로와 처리 기준을 공개한다.
- [ ] 운영자가 신고 개인정보를 필요한 범위에서만 조회하도록 제한한다.
- [ ] 차단/삭제된 콘텐츠가 피드·검색·주변 추천·대기열에서 어떻게 처리되는지 검증한다.
- [ ] 관리자 조작·계정 정지·이의제기 처리 이력을 남긴다.

완료 증거: 앱 신고부터 관리자 확인·조치까지 실제 처리하고, 조치 후 공개 접근 차단을 확인한다. 신고 버튼만으로 완료 처리하지 않는다.

### SEC-01 / MED-01 / OPS-01 — 안정성과 운영

- [ ] 로그인·검색·신고·업로드별 요청 제한과 사용자별 일일/전체 저장량 쿼터를 설계한다. 현재 미완료 업로드 10개 제한만으로 전체 남용을 막을 수는 없다.
- [ ] 세션 만료 UX, 로그아웃/계정 정지/탈퇴 시 무효화 범위, 비밀키 교체 절차를 정한다.
- [ ] 관리자 MFA 및 최소 권한, 운영 환경 접근·비밀값 관리 절차를 마련한다.
- [ ] 격리된 처리 환경에서 파일의 디코딩 가능 여부·코덱·실제 길이·손상 여부를 검사한다. 현재 헤더·해시 검사는 콘텐츠의 정상 재생이나 권리 적법성을 증명하지 않는다.
- [ ] 압축 파일 가져오기에서 허용 형식·개수·총 해제 용량·경로 탈출·중첩 압축·취소 동작의 방어와 테스트를 재확인한다.
- [ ] 최초 오디오 출시 시 웹/API의 쇼츠·게시글 제출도 비활성화하거나 명시적으로 제한한다.
- [ ] DB 백업 및 복원 훈련, R2 보존·삭제·복구 정책, 마이그레이션 롤백 절차를 마련한다.
- [ ] 실패율·지연·스토리지 사용량·비용 알림과 담당 연락망을 구성한다.
- [ ] 토큰·업로드 URL·정밀 좌표·신고 본문 등이 로그에 불필요하게 남지 않는지 실제 배포 설정까지 확인한다.
- [ ] 공개 미디어의 Range 재생·동시 요청·삭제 반영과 캐시 전략을 부하 테스트한다.

운영 설정은 이번 점검에서 확인하지 못했다. 별도 환경에 이미 구현되어 있다면 증거를 연결한 뒤 체크한다.

## 5. 프론트엔드 작업과 완료 조건

### APP-01 — 앱 시작 실패 대응

[MainActivity.kt](../app/src/main/java/com/kimyubin33/audioapp/MainActivity.kt)는 MediaController 연결에 실패하면 null로 처리하고, controller가 있을 때만 AppNavigation을 그린다. 연결 실패 시 빈 화면으로 남을 가능성이 있다.

- [ ] 연결 상태를 로딩·성공·실패로 분리한다.
- [ ] 시간 초과·오류 설명·재시도 화면을 제공한다.
- [ ] 재시도·화면 재생성·서비스 종료 시 컨트롤러 중복 연결 및 해제를 검증한다.

완료 증거: 서비스 연결 실패를 재현해 빈 화면이 아닌 복구 가능한 화면이 표시되는지 확인한다.

### MED-01 — 업로드와 재생 복구

[CreatorViewModel.kt](../app/src/main/java/com/kimyubin33/audioapp/ui/CreatorViewModel.kt)는 초안과 업로드 ID를 저장하고 서버 상태를 재확인하지만 전송 작업은 ViewModel 수명에 연결되어 있다.

- [ ] 업로드를 화면 내 작업으로 제공할지 백그라운드 지속 전송으로 제공할지 결정한다.
- [ ] 앱 종료·화면 회전·통신 전환·토큰 만료·취소 후 중복 콘텐츠 없이 복구되는지 검증한다.
- [ ] 업로드 진행·실패 원인·재시도·검수 대기·반려 사유를 사용자가 구분할 수 있게 한다.
- [ ] 실패한 파일은 재검증하고 완료된 전송은 불필요하게 다시 보내지 않도록 한다.
- [ ] 화면 잠금 장시간 재생, 전화/다른 앱 오디오 포커스, 블루투스 해제·재연결을 검증한다.
- [ ] 통신 단절·느린 회선·버퍼링·미디어 삭제·토큰 만료 후 재생 복구를 검증한다.

### UX-01 — 보관함·권한·접근성

- [ ] 보관함이 파일 다운로드가 아닌 저장 목록이라는 점과 로컬 저장 범위를 명확히 안내한다.
- [ ] 현재 로컬 프로필·청취 기록·보관 목록의 계정 전환 및 삭제 의미를 확인한다.

- [ ] 위치를 거부/철회하거나 대략적 위치만 허용해도 기본 오디오 기능이 동작하는지 확인한다.
- [ ] 최초 주변 탐색 전에 좌표의 서버 전송·목적·실제 보유 여부·끄는 방법을 설명한다. 권한 거부 후 rationale 화면만으로 대체하지 않는다.
- [ ] 넓은 오디오 지역 탐색에 정밀 위치가 필요한지 재검토하고, 실제 필요한 기능에서만 요청한다.
- [ ] 알림 거부 상태의 재생·잠금화면·서비스 동작을 검증한다.
- [ ] TalkBack, 큰 글꼴, 터치 영역, 명도 대비, 가로/작은 화면, 시스템 애니메이션 비활성화를 확인한다.
- [ ] 검색 결과 없음·구독 없음·서버 장애·로그인 만료 상태에서 다음 행동을 제공한다.

## 6. 정책 문서·동의 설계

### 필요한 문서

- [ ] 서비스 이용약관: 계정, 서비스 범위, 금지 행위, 제재·탈퇴·분쟁·문의.
- [ ] 개인정보처리방침: 실제 항목·목적·근거·보유 기간·위탁/제공·국외 이전·이용자 권리·담당 연락처.
- [ ] 커뮤니티/업로드 정책: 금지 콘텐츠, AI 표시, 사칭·저작권·개인정보 침해, 검수·삭제·이의제기.
- [ ] 크리에이터 이용조건: 플랫폼의 저장·전송·공개 재생에 필요한 이용허락 범위, 공개 중단 및 탈퇴 처리.
- [ ] 계정 삭제 안내 및 웹 요청 페이지.
- [ ] 위치 기능의 처리 안내와 국내 위치정보법 적용 여부에 따른 약관·동의·사업상 의무 검토.
- [ ] 대상 연령·미성년자 정책 및 적용되는 아동 안전 기준.

문서는 실제 사업자·운영 환경을 반영해야 한다. Google 로그인 안내가 우리 서비스의 약관 수락을 대신하지 않는다. 개인정보처리방침의 공개와 동의를 법적 근거로 하는 개인정보 처리의 동의는 구별한다.

## 9. 다음 개발 세션 시작 절차
