# 신고 처리 및 오디오 전용 출시

기준일: 2026-11-12. 로컬 구현과 운영 연결 절차다. 실제 운영 배포·처리 담당자 배정은 별도다.
[출시 체크리스트](google-play-release-readiness.md)와 함께 관리한다.

## 사용자 흐름

재생 화면의 신고에서 **이 오디오 / 크리에이터**를 선택한다.
사유는 스팸·부적절한 내용·저작권·AI 표시·기타이며, 기타는 설명을 요구한다.
사칭·개인정보 노출은 기타 설명으로 접수한다. 불필요한 개인정보를 적지 않도록 안내한다.
별도 증거 파일을 업로드하거나 외부 주소를 자동으로 열지 않는다. 설명에 적힌 근거는 운영자가 검토하는 진술이다.

보관함 → 계정 → **신고 내역**에서 접수 번호·상태·처리 사유를 조회한다.
이 화면은 로그인한 신고자 본인의 자료만 반환하며, 페이지 넘김·새로고침·실패 재시도를 지원한다.
이의 제기는 접수 번호와 함께 운영 문의로 전달하도록 안내하고 약관 화면에 SUPPORT_EMAIL을 표시한다.
실제 문의 주소, 처리 기한, 이의제기 담당자와 접수·재심 기록 운영은 아직 확정해야 한다.
푸시/이메일 자동 통지와 신고 대상자 전용 이의제기 화면은 이번 구현에 포함하지 않는다.

## API

| 경로 | 권한 / 동작 |
| --- | --- |
| POST /v1/reports | 로그인. content_id 또는 creator_id 중 정확히 하나와 reason, 선택 detail |
| GET /v1/me/reports | 본인 신고 상태/공개 처리 사유. limit·cursor 페이지 |
| GET /v1/admin/reports?status=open | 관리자 전용 처리 대기열. 상태·cursor 페이지 |
| GET /v1/admin/reports/{id} | 관리자 전용 신고 설명·대상 버전·최근 처리 이력 |
| POST /v1/admin/reports/{id}/review | 관리자 전용. action, revision, resolution, confirmed:true |

신고는 동일 사용자·동일 대상에 대해 한 건으로 유지한다. 재요청은 기존 신고를 덮어쓰지 않는다.
사용자별 최근 24시간의 **새 신고는 20건**으로 제한한다. 중복 재시도는 상한에 포함하지 않는다.
오디오와 크리에이터 신고를 합산하며 동시 요청에서도 SQL 조건으로 상한을 검사한다.
이는 신고 생성 제한일 뿐, 로그인·검색·전송의 전체 요청 제한을 대신하지 않는다.

관리자 상세 응답에는 신고자의 사용자 ID나 Google 식별자를 포함하지 않는다.
신고 설명은 개인정보를 포함할 수 있으므로 관리자만 조회한다. 일반 목록·본인 목록에 다른 신고자의 설명을 노출하지 않는다.
처리 사유는 신고자에게 표시되므로 내부 메모나 제3자의 개인정보를 쓰지 않는다.

## 운영자 화면

`/admin` 경로의 **신고 처리**에서
접수 → 검토 중 → 조치 완료 / 기각 상태를 관리한다. 각 조치에 사유와 확인 체크가 필요하다.

- 검토 시작: 접수를 검토 중으로 변경한다.
- 기각: 사유를 남기고 신고를 닫는다.
- 콘텐츠 공개 중단: 해당 콘텐츠를 removed로 전환한다. R2 원본 즉시 삭제 기능은 아니며 별도 보존 정책을 따른다.
- 업로드 권한 회수: 대상 크리에이터를 일반 사용자로 변경한다. 기존 콘텐츠 공개 중단과 계정 로그인 정지는 별개다.

신고 revision과 콘텐츠 revision을 확인해 오래된 화면의 조치를 거부한다.
SQLite 트리거 안에서 조치·신고 결과·감사 이력을 한 트랜잭션으로 반영한다.
동시 처리 중 하나만 성공하며 충돌하면 최신 상세를 다시 읽고 판단한다.
이미 종료된 신고를 직접 수정하거나 조치 버튼으로 재처리하지 않는다.
전체 계정 정지, 업로드 권한 복구의 이의제기 연계, 복구/재심 감사는 후속 작업이다.

## 데이터 변경과 삭제

0009_report_workflow.sql은 기존 콘텐츠 신고를 보존하면서 creator_id, 상태·버전·처리 결과와 report_events를 추가한다.
기존 신고는 open 상태로 이관된다. 먼저 0008까지 적용하고 0009를 적용한 뒤 새 Worker를 배포한다.
운영 적용 전 백업과 복구 절차를 준비한다. 개발 DB 초기화로 기존 신고 보존 검증을 우회하지 않는다.

계정 삭제 시 본인이 제출한 신고와 해당 크리에이터/콘텐츠 신고를 삭제하고 이력은 FK cascade로 함께 정리한다.
다른 신고를 처리한 삭제 계정의 운영자 ID는 익명화한다.
법정 보존이 필요하면 회사에서 근거·기간·최소 자료를 확정한 뒤 별도 설계해야 한다.

## 오디오 전용 범위

운영 모드에서는 오디오만 제출·수정·승인·공개 조회·공개 미디어 제공·주변 탐색이 가능하다.
기존 쇼츠/게시글 데이터·원본·브라우저 초안은 보존한다. 소유자/관리자 검수 접근은 남아 있다.
이전 영상 업로드 티켓도 파일 PUT과 complete에서 거부한다.
서버가 format_unavailable을 반환하면 오디오로 다시 제출하도록 안내한다.

웹은 오디오·ZIP 추가만 노출하고 영상 가져오기와 기존 영상/게시글 초안 제출을 차단한다.
기존 전체 형식 회귀 테스트에서만 DEV_MODE=1 및 ENABLE_EXTENDED_FORMATS=1을 동시에 지정한다.
운영에서 ENABLE_EXTENDED_FORMATS만 켜도 확장되지 않는다. 후속 출시 시 정책·UI·API 범위를 함께 변경한다.
기존 이미 공개된 외부 파일 URL·클라이언트 버퍼에 전달된 바이트까지 회수할 수 있다고 안내하지 않는다.

## 검증 및 남은 운영 작업

검증: 서버 test/reports.test.mjs, 기존 데이터 migration 테스트, 웹 e2e/creator.spec.mjs,
Android ReportsInstrumentedTest에서 권한·중복·조치·본인 결과·화면 흐름을 확인한다.
2026-11-12 서버 65개, 웹 E2E 10개, AAOS 에뮬레이터 계측 테스트 5개가 통과했다.
Android 빌드·단위 테스트·lint와 TypeScript 검사를 통과했고 Rust 테스트 42개가 통과했다(1개 ignored).
로컬 개발 DB에 0009를 적용했다. 운영 DB 적용과 Worker 배포는 수행하지 않았다.
실행 결과는 출시 체크리스트의 이력에 함께 기록한다.

출시 전 실제 관리자 계정으로 전 과정을 수행하고 담당자·처리 기한·신고 기준·문의 주소를 확정한다.
계정 정지·이의제기·알림, 관리자 MFA, 전체 API 요청 제한, 실제 미디어 검사, 운영 환경 검증은 남아 있다.
사용자별 저장 용량·일일 업로드 쿼터는 후속 구현했으며 [용량 운영 절차](upload-quota-operations.md)를 따른다.
